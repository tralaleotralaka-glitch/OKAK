# MySENGER

Мессенджер на чистом HTML/CSS/JS без сборки и зависимостей.
Контакты добавляются по номеру телефона, вся переписка, контакты и настройки
хранятся в браузере (`localStorage`) и переживают перезапуск.

## Как это работает

| Что | Где | Как ведёт себя |
| --- | --- | --- |
| **Новый чат** | значок **«+»** в правом нижнем углу | открывает лист ввода номера: выбираете код страны, вводите номер — появляется кнопка **«Применить»** (неактивна, пока номер неполный). После «Применить» вы попадаете в диалог с этим номером |
| **Настройки** | шестерёнка в правом верхнем углу | смена **аватарки** и **имени**, **тема** (светлая / тёмная / системная), демо-ответы, отправка по Enter, выгрузка копии и очистка данных |
| **Выход из настроек** | кнопка «←» или область вне панели | если есть несохранённые изменения — спросит: **Сохранить / Не сохранять / Отмена**. Тема применяется сразу, чтобы её можно было посмотреть до сохранения |
| **Сохранение** | автоматически | каждое действие (контакт, сообщение, настройка) сразу пишется в `localStorage`; в шапке мелькает «Сохранено ✓». После выхода из мессенджера и повторного входа на месте контакты, переписка, имя, аватар и тема |
| **Поиск** | поле над списком | по имени или по цифрам номера |
| **Карточка контакта** | клик по шапке диалога | переименовать, поставить фото, удалить контакт вместе с перепиской |

Номер вводится в маске и приводится к одному формату, поэтому `+7 912 345-67-89`,
`89123456789` и вставка номера целиком не создают дубликат контакта.

## Запуск

```bash
npm start            # python3 -m http.server 8000 --bind 0.0.0.0
# или любой другой статический сервер:
npx serve .
```

и откройте `http://localhost:8000`.

Просто открыть `index.html` двойным кликом не получится: приложение собрано
из ES-модулей, а браузеры не грузят их по протоколу `file://`.

## Тесты

```bash
npm install          # нужен только jsdom для сквозных тестов интерфейса
npm test
```

- `tests/phone.test.js` — разбор, валидация и маски номеров;
- `tests/store.test.js` — состояние и хранилище (сохранение, дубликаты, непрочитанные, очистка);
- `tests/ui.test.js` — отрисовка и экранирование;
- `tests/app.test.js` — сквозной сценарий в jsdom: клик по «+» → ввод номера →
  «Применить» → сообщение → настройки → сохранение → «перезапуск» и проверка,
  что всё восстановилось.

## Устройство

```
index.html        разметка: список чатов, диалог, лист номера, панель настроек, модалки
css/styles.css    светлая и тёмная темы на CSS-переменных, мобильная раскладка
js/phone.js       номера: маска ввода, валидация, формат вывода      (чистый модуль)
js/store.js       состояние и localStorage                          (чистый модуль)
js/ui.js          отрисовка, экранирование, сжатие аватара в canvas
js/app.js         связывает всё: события, оверлеи, сохранение
scripts/          сборка www/ для упаковки в APK
android/          нативный Android-проект (Capacitor + WebView)
tests/            тесты на node:test
.github/workflows автоматическая сборка APK
```

`js/phone.js` и `js/store.js` не знают про DOM и не зависят от хранилища —
оно передаётся параметром, поэтому их можно прогонять в Node.

## APK для Android

Мессенджер упакован в Android-приложение через [Capacitor](https://capacitorjs.com):
`android/` — нативный проект с WebView, веб-часть кладётся в
`android/app/src/main/assets/public`.

**Скачать готовый APK:** раздел [Releases](../../releases) — файл
`app-debug.apk` в релизе `apk-<имя-ветки>` (например `apk-main`).
Подпись отладочная, поэтому при установке Android попросит разрешить
«Установку из неизвестных источников».

**Собрать самому** (нужны JDK 21 и Android SDK, например через Android Studio):

```bash
npm install
npm run apk        # = build:web → cap sync android → ./gradlew assembleDebug
# APK появится в android/app/build/outputs/apk/debug/app-debug.apk
```

`npm run android:open` откроет проект в Android Studio.

**Автоматически.** Каждый `git push` запускает workflow
[`.github/workflows/android.yml`](.github/workflows/android.yml):
прогоняет тесты, собирает `www/`, синхронизирует Android-проект,
выполняет `gradlew assembleDebug`, прикладывает APK к артефактам прогона
и обновляет релиз `apk-<имя-ветки>`. Прогресс — на вкладке **Actions**.

Полезные команды:

| Команда | Что делает |
| --- | --- |
| `npm run build:web` | складывает `index.html`, `css/`, `js/` в `www/` |
| `npm run sync:android` | `build:web` + копирование в `android/` (`cap sync`) |
| `npm run apk` | собирает APK через Gradle |

В `android/.gitignore` сгенерированные файлы (`assets/public`, `capacitor.config.json`,
`capacitor-cordova-android-plugins`) не хранятся — их пересоздаёт `cap sync`,
поэтому в репозитории только исходники нативного проекта.

## Где лежат данные

Один ключ `mysenger.state.v1` в `localStorage` текущего браузера:

```jsonc
{
  "version": 1,
  "profile":  { "name": "Алексей", "avatar": "data:image/jpeg;…", "color": "#6c5ce7" },
  "contacts": [{ "id": "c_79123456789", "name": "Мама", "phone": "+79123456789" }],
  "chats":    { "c_79123456789": { "messages": […], "unread": 0, "updatedAt": 1728470000000 } },
  "settings": { "theme": "dark", "autoReply": false, "enterToSend": true }
}
```

Аватар ужимается в canvas до 256×256 JPEG, чтобы не упираться в квоту ~5 МБ.
Кнопка «Выгрузить копию» в настройках отдаёт этот же JSON файлом.

## Ограничения

Сервера нет: сообщения видны только на этом устройстве, а «Демо-ответы»
в настройках имитируют собеседника, чтобы переписку можно было посмотреть
вживую. Подключить настоящий бэкенд — значит заменить `store.saveState`/`loadState`
на запросы к API: остальной код от хранилища не зависит.
